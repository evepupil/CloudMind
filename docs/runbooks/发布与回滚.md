# 发布与回滚 Runbook

本文说明 CloudMind 的版本、自动发布、生产冒烟和 Worker 回滚流程。数据导出与
fresh-resource 恢复见[数据导出与恢复 Runbook](数据导出与恢复.md)。

## 发布边界

- `package.json` 使用 Semantic Versioning。0.x 阶段的 minor 允许调整尚未稳定的
  API，patch 只包含兼容修复。
- 每个待发布版本必须在 `CHANGELOG.md` 中有带日期的同版本条目。
- Worker 代码支持版本回滚；D1 migration 只向前执行，发布脚本不会自动撤销表结构。
- 原始数据、导出包和恢复能力由 M6 管理；本流程只负责版本上线和快速止损。

## Cloudflare Workers Builds 设置

生产 Worker 的 Git 集成监听 `main`，使用以下设置：

```text
Build command:  npm run build
Deploy command: pnpm release:deploy
Build variable: SMOKE_BASE_URL=https://cloudmind.chaosyn.com
```

`JINA_API_KEY` 等敏感值继续使用 secret build variable。禁止把密钥写入仓库、
普通 build variable 或发布日志。

首次私有部署还没有公开 URL 时，执行 `pnpm deploy:one-click`。它会调用
`deploy:first`，完成 migration 核验与 Worker 发布，并暂时跳过生产冒烟。绑定域名后
必须补跑：

```powershell
$env:SMOKE_BASE_URL='https://your-cloudmind.example.com'
pnpm release:smoke
Remove-Item Env:SMOKE_BASE_URL
```

## Migration 兼容规则

Worker 回滚不会回退 D1。所有 migration 都必须兼容发布前后的 Worker：

1. 先新增可空字段、新表或新索引，让旧代码继续运行。
2. 新 Worker 上线后再开始写入新结构，读取路径保留旧数据兼容。
3. 数据回填完成并经过至少一个稳定发布周期后，才能移除旧字段或旧表。
4. 重命名使用“新增、双读写、回填、移除旧结构”的多次发布流程。
5. 禁止在同一次发布中直接删除线上 Worker 仍会读取的结构。

## 自动发布流程

推送 `main` 后，Cloudflare Workers Builds 先执行构建，再执行
`pnpm release:deploy`：

```text
读取发布前 Worker version
  -> 校验 package version 与 CHANGELOG
  -> 应用远端 D1 migrations
  -> 精确核对本地与远端 migration 名称和顺序
  -> 发布 Worker
  -> 检查 /api/health、/login、未鉴权 /mcp
  -> 成功结束，或把 Worker 回滚到发布前 version
```

生产冒烟要求：

- `/api/health` 返回 `200`，JSON 中 `ok=true`、`service=cloudmind`。
- `/login` 返回 `200` 和 HTML。
- 未携带凭据调用 `/mcp` 返回 `401`。

本地发布使用同一条链路：

```powershell
$env:SMOKE_BASE_URL='https://cloudmind.chaosyn.com'
pnpm deploy
Remove-Item Env:SMOKE_BASE_URL
```

## 手动回滚

先查看版本和部署记录：

```powershell
pnpm exec wrangler versions list
pnpm exec wrangler deployments list
```

确认目标 version ID 后执行：

```powershell
$env:SMOKE_BASE_URL='https://cloudmind.chaosyn.com'
pnpm release:rollback -- --version <worker-version-id>
Remove-Item Env:SMOKE_BASE_URL
```

脚本切换 Worker 后会立即运行生产冒烟。发现 split traffic 时，自动发布和演练会拒绝
选择回滚目标，需要先人工确认流量配置。

## 回滚演练

演练会读取最近两个不同的 100% 生产版本，先切到上一版本并冒烟，再恢复开始时版本并
再次冒烟：

```powershell
$env:SMOKE_BASE_URL='https://cloudmind.chaosyn.com'
pnpm release:rollback:rehearse
Remove-Item Env:SMOKE_BASE_URL
```

演练中断时，`finally` 恢复开始时版本。恢复也失败时，立即停止后续发布，使用
`pnpm exec wrangler deployments status` 核对线上版本，并按手动回滚流程处理。

## 发布核对

每次稳定发布至少保留以下证据：

- 本地 `pnpm gate` 和 `git diff --check` 通过。
- GitHub Quality Gate 通过。
- Cloudflare Build 日志包含 migration apply、migration verify、Worker deploy 和
  production smoke。
- `pnpm release:rollback:rehearse` 完成，结束时生产 version 与演练开始时一致。
- 最终 `/api/health` 返回 `200`。
