# 数据主权与生命周期

> 模块定位：保证原始输入不可变，并让个人数据可完整导出、重建和迁移。
>
> 对应代码：`src/core/{assets,blob,vector}/*`、`src/features/{assets,workflows}/server/*`、`src/platform/{blob,db,vector}/*`、`scripts/ops/*`
>
> 所属 M 里程碑：[`M6 数据主权与生命周期`](../roadmap.md#m6-数据主权与生命周期)
>
> 当前状态：进行中
>
> 最近更新时间：2026-07-24

## 职责与边界

- 为文本、MCP 和 Agent 输入保存独立、不可变的原始快照。
- 导出 D1 中的 library、memory、图谱、来源和任务元数据。
- 导出 R2 原始内容与清洗结果，并提供可校验的清单。
- 定义软删除、恢复、专用 forget 和可选硬删除的清晰语义。
- 提供脱离当前 Cloudflare 资源后的重建说明和验证流程。

## 结构与数据流

```text
stage A input        -> immutable R2 snapshot -> asset/memory processing
stage B D1 + R2      -> manifest -> versioned JSON/NDJSON + files
export package       -> validation -> fresh resources -> rebuild vectors
forget request       -> scoped lifecycle policy -> D1/R2/vector cleanup
```

## 关键决策

1. 原始资产必须进入导出包，AI 派生内容可以选择重建。
2. 向量不作为唯一数据源，迁移时允许从文本重新生成。
3. 默认 forget 采用可恢复策略，硬删除需要显式选择和完整清理。
4. 导出格式不绑定 D1、R2 或 Vectorize 的内部表示。
5. M6 分阶段交付：阶段 A 在 M3 结构化记忆写入前完成不可变输入；阶段 B 在 M3 后完成
   导出、导入、重建和恢复演练。
6. M3 提供 `forget` 产品入口和用户操作，M6 定义跨存储删除、恢复、审计与重建规则。
7. 文本快照固定写入 `assets/<assetId>/raw/input.txt`，保留输入的 UTF-8 字节语义，
   包括首尾空格和换行形式；派生处理只清理读取后的工作副本。
8. D1 的 `rawR2Key` 只允许首次绑定。相同 key 可重复绑定，不同 key 视为冲突；
   已绑定但 R2 对象缺失时任务失败，禁止从可能变化的 D1 正文重建原文。
9. R2 写入成功、D1 绑定失败时，工作流重试会读取固定 key 的现有对象并补写指针。
10. Agent 记忆默认只保存选中的高密度内容。完整会话仅在用户显式归档时作为
    `recordKind=library` 进入导出范围。

## 当前实现

- 阶段 A 已完成。Web 文本、MCP `save_asset`、`remember` 和 `remember_agent` 共用
  `note_ingest_v1`，首个 `load_source` 步骤先保存或读取不可变 R2 快照，再进入
  清洗、摘要、图谱提取与索引。
- 文本快照成功后才绑定 D1 `rawR2Key`；R2 写入失败由现有 Queue 重投，完整输入在
  D1 中保留到快照成功。重处理只读取已归档原文，不覆盖固定 raw key。
- URL 和 PDF 继续使用各自的独立 R2 原始对象。
- 专用 `forget` 已按精确 scope/context 软删除 memory 并清理 chunk 向量；清理失败会
  明确回报 pending，D1 过滤仍立即阻止该记录进入检索。
- 专用 `restore_memory` 会恢复记录并从不可变 R2 快照重新进入处理流水线，重建
  chunk、Vectorize 和派生内容；排队失败会回滚到软删除状态。
- memory 更新保留每版不可变输入和版本链；旧版 L2 数据的物理清理、硬删除和删除
  审计仍由阶段 B 统一约束。
- repository、blob 和 vector 端口为迁移保留了边界。
- 已有 fresh D1/Vectorize 初始化和 scope 向量运维脚本。
- 阶段 B 的数据包 v1 已落地：`data:export` 通过 Wrangler 分页读取 D1 正式引用的
  R2 key 和 Vectorize ID，生成 D1 SQL、R2 文件、两个向量 NDJSON 与逐文件 SHA-256
  清单；文件校验使用流式哈希，避免整文件载入内存。
- `data:validate` 可完全离线校验清单、路径边界、文件大小和校验和。
- `data:restore` 只接受显式命名的隔离资源，恢复前检查 Vectorize metadata 索引，
  随后导入 D1、核对各表行数、上传 R2 并 upsert 向量。`--resume` 仅在目标 D1 与
  清单逐表一致时放行。
- 完整步骤见 [数据导出与恢复 Runbook](../runbooks/数据导出与恢复.md)。
- BlobStore 当前仍只有按 key 写入和读取；数据包导出以 D1 正式引用为准，故不包含
  bucket 中未绑定的孤立对象。
- fresh-resource 恢复演练、R2 回读抽查和硬删除审计仍待完成。

## 验证方式

- 阶段 A：单元测试覆盖精确保留原文、只读重处理、中断恢复、对象缺失和 R2 失败；
  Workers 集成测试通过真实 Miniflare D1 + R2 验证指针绑定、幂等与覆盖冲突。
- 阶段 B：用固定数据集执行“导出 -> 新资源导入 -> 重建向量 -> 查询核对”，并验证
  软删除、恢复和硬删除后的 D1、R2、Vectorize 一致性。
- 数据包核心单测覆盖结构、交叉引用、路径穿越、文件篡改、恢复续跑与目标污染保护。
