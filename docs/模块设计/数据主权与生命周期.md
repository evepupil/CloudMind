# 数据主权与生命周期

> 模块定位：保证原始输入不可变，并让个人数据可完整导出、重建和迁移。
>
> 对应代码：`src/core/{assets,blob,vector}/*`、`src/features/assets/server/*`、`src/platform/{blob,db,vector}/*`、`scripts/ops/*`
>
> 所属 M 里程碑：[`M6 数据主权与生命周期`](../roadmap.md#m6-数据主权与生命周期)
>
> 当前状态：未开始
>
> 最近更新时间：2026-07-23

## 职责与边界

- 为文本、MCP 和 Agent 输入保存独立、不可变的原始快照。
- 导出 D1 中的资产、情节、图谱、来源和任务元数据。
- 导出 R2 原始内容与清洗结果，并提供可校验的清单。
- 定义软删除、恢复、专用 forget 和可选硬删除的清晰语义。
- 提供脱离当前 Cloudflare 资源后的重建说明和验证流程。

## 结构与数据流

```text
stage A input        -> immutable R2 snapshot -> asset/episode processing
stage B D1 + R2      -> manifest -> versioned JSON/NDJSON + files
export package       -> validation -> fresh resources -> rebuild vectors
forget request       -> scoped lifecycle policy -> D1/R2/vector cleanup
```

## 关键决策

1. 原始资产必须进入导出包，AI 派生内容可以选择重建。
2. 向量不作为唯一数据源，迁移时允许从文本重新生成。
3. 默认 forget 采用可恢复策略，硬删除需要显式选择和完整清理。
4. 导出格式不绑定 D1、R2 或 Vectorize 的内部表示。
5. M6 分阶段交付：阶段 A 在 M3 自动捕获前完成不可变输入；阶段 B 在 M3 后完成
   导出、导入、重建和恢复演练。
6. M3 提供 `forget` 产品入口和用户操作，M6 定义跨存储删除、恢复、审计与重建规则。

## 当前实现

- URL 和 PDF 已有独立 R2 原始对象；文本、MCP 和 Agent 输入仍只依赖 D1
  `contentText`，`rawR2Key` 为空，尚未形成不可变原始快照。
- 已有通用软删除与恢复，但恢复不会重建 Vectorize 索引。
- repository、blob 和 vector 端口为迁移保留了边界。
- 已有 fresh D1/Vectorize 初始化和 scope 向量运维脚本。
- BlobStore 当前只有按 key 写入和读取，尚无导出所需的枚举与流式读取能力。
- 尚无整库导出命令、版本化清单、导入流程、恢复演练或专用 forget 动词。

## 验证方式

完成后需用固定数据集执行“导出 -> 新资源导入 -> 重建向量 -> 查询核对”，并验证
软删除、恢复和硬删除后的 D1、R2、Vectorize 一致性。

## 待扩展项

- 阶段 A：文本、MCP 和 Agent 输入的不可变 R2 快照，以及写入失败时的降级测试。
- 阶段 B：版本化、分页或流式 JSON/NDJSON、R2 文件与 checksum manifest 导出。
- 阶段 B：可重复执行的导入、向量重建 runbook 和固定数据集恢复演练。
- 配合 M3 的 `forget` 补齐删除审计、完整清理、恢复重索引和过期数据策略。
