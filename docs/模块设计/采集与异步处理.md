# 采集与异步处理

> 模块定位：把 URL、文本和 PDF 安全保存为资产，并完成可重试的派生处理。
>
> 对应代码：`src/features/ingest/*`、`src/features/workflows/*`、`src/core/assets/*`、`src/platform/blob/*`、`src/platform/queue/*`
>
> 所属 M 里程碑：[`M0 采集与异步处理`](../roadmap.md#m0-采集与异步处理)
>
> 当前状态：已完成
>
> 最近更新时间：2026-07-24

## 职责与边界

- 校验 URL、文本和 PDF 输入，创建资产和原始来源记录。
- 在已有来源能力范围内保存原始内容，把处理任务交给 Queue 和 workflow runtime。
- 完成清洗、摘要、分类、分块、embedding、索引和状态收尾。
- 搜索排序、知识图谱语义和页面展示由下游模块负责。

## 结构与数据流

```text
Web / REST / MCP
  -> ingest service -> D1 asset -> immutable R2 raw snapshot
  -> queue -> type workflow -> shared steps
  -> clean content + metadata + chunks + vectors -> ready / failed
```

URL、文本和 PDF 各自保留来源加载步骤，后续公共处理由
`shared-workflow-steps.ts` 统一编排。

## 关键决策

1. 原始输入是可追溯的真相来源；URL、PDF 和文本类输入均在派生处理前保存 R2
   原始对象，派生内容允许删除后重算。
2. URL 重处理读取首次保存的 R2 原始快照，不重新抓取远端内容，也不覆盖快照。
3. feature 层依赖 AssetRepository、BlobStore、VectorStore、JobQueue 和
   AIProvider 端口，Cloudflare 细节留在 platform 层。
4. 每个步骤保存状态和错误，失败任务可重试并可在 Activity 查看。

## 当前实现

- `note_ingest_v1`、`url_ingest_v1`、`pdf_ingest_v1` 三条工作流。
- 结构保留清洗、token 感知切块、增量 embedding 和 Vectorize 写入。
- PDF 文本抽取、URL Reader 回退、AI 派生失败降级和任务状态记录。
- Web、REST 与 MCP 复用服务边界。
- URL 与 PDF 使用各自的 R2 原始对象。Web 文本、MCP 与 Agent 输入共用
  `note_ingest_v1`，其首个 `load_source` 步骤将原始 UTF-8 内容写入固定 R2 key，
  再把归档内容交给公共处理步骤。
- 文本重处理读取已绑定快照；R2 已写而 D1 指针尚未写入时，重试会恢复绑定。
  已绑定对象缺失或尝试更换 raw key 时直接失败，避免把可变正文当作原文。

## 验证方式

运行完整项目门禁，重点单测位于 `tests/unit/features/ingest/` 和
`tests/unit/features/workflows/`。Workers 集成测试使用 Miniflare D1 + R2 验证文本
快照的真实存储行为；PDF 固定样本位于 `tests/fixtures/ingest/`。

## 待扩展项

- 浏览器扩展采集入口。
- 图片 OCR、音视频转录和更多文件格式。
- 用户显式保存完整对话时按 library 资产进入现有工作流；默认 Agent 记忆只保存
  选中的高密度内容。
