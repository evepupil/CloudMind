# 工程质量与发布

> 模块定位：维护严格类型、静态检查、测试、检索评估、构建和发布门禁。
>
> 对应代码：`tsconfig.json`、`biome.json`、`package.json`、`tests/*`、`scripts/*`、`.gitattributes`
>
> 所属 M 里程碑：[`M7 工程质量与发布`](../roadmap.md#m7-工程质量与发布)
>
> 当前状态：进行中
>
> 最近更新时间：2026-07-23

## 职责与边界

- TypeScript strict 和 Biome 负责类型、格式与静态规则。
- Vitest 覆盖核心服务、repository 边界、纯函数和回归行为。
- eval 独立检查检索各阶段，生产构建检查 HonoX 和样式产物。
- 发布流程负责版本、迁移、构建、部署与回滚说明。

## 结构与数据流

```text
source + docs
  -> typecheck -> lint -> unit/integration tests -> retrieval eval -> build
  -> CI + infrastructure checks -> version/release -> deploy -> smoke / rollback
```

## 关键决策

1. `noExplicitAny`、未使用代码、type-only import 等规则按 error 执行。
2. 核心业务逻辑必须有单测，纯视觉改动使用人工检查。
3. eval 既检查最终指标，也保留各检索阶段指标，便于定位回归。
4. 文档中的完成状态必须有测试、可运行功能、提交或人工确认支撑。
5. M7 分为开发前置门禁和发布收尾；前置门禁先保护后续数据模型与生命周期改动。

## 当前实现

- strict TypeScript、Biome 零 warning、Vitest 和 25 条检索 eval。
- 当前基线为 35 个测试文件、278 个测试全部通过。
- `pnpm typecheck`、`pnpm lint`、`pnpm test`、`pnpm eval`、`pnpm build`
  组成完整本地门禁。
- 仓库当前没有 CI workflow，`package.json` 版本仍为 `0.1.0`。
- Cloudflare 绑定类型尚未纳入自动生成与漂移检查，队列幂等、DLQ 和 Workers
  集成路径也缺少统一门禁。

## 验证方式

提交前依次运行五项本地门禁并保存失败信息。建立 CI 后，同一组命令必须在干净
环境自动执行，发布还需验证迁移和部署脚本。

## 待扩展项

- 前置门禁：增加持续集成并固定 Node、pnpm 与 lockfile 行为。
- 前置门禁：自动生成并校验 Cloudflare 绑定类型，检查密钥配置边界，覆盖队列
  幂等、DLQ 和 Workers 集成路径。
- 发布收尾：建立语义化版本、CHANGELOG、迁移说明和发布/回滚 runbook。
- 发布收尾：增加真实 Cloudflare 环境的受控冒烟与部署后检查。
