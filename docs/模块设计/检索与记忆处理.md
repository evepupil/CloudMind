# 检索与记忆处理

> 模块定位：负责混合检索、Workers AI 重排，以及摄取流程中的知识图谱抽取与实体消歧。
>
> 对应代码：`src/features/search/server/*`、`src/features/workflows/server/shared-workflow-steps.ts`、`src/platform/ai/workers-ai/workers-ai-provider.ts`
>
> 所属里程碑：[`P1 检索地基`](../memory-layer-roadmap.md#p1--检索地基--retrieval-foundation)
>
> 当前状态：已完成，持续维护
>
> 最近更新时间：2026-07-22

## 职责与边界

- 检索模块并行读取 Vectorize、D1 FTS5 和 L2 图谱结果，融合后调用重排与 MMR 去重。
- Workers AI 适配器只负责模型请求和响应转换，业务层通过 `AIProvider` 调用，不直接依赖具体模型。
- 工作流在正文清洗后抽取实体与陈述；图向量用于同一 scope 内的实体合并。
- D1、Vectorize、Workers AI 的装配留在 platform 层，feature 层只依赖端口。

## 结构与数据流

```text
query -> dense + FTS5 + graph -> 融合 -> bge-reranker -> MMR -> 证据分组

clean content -> graph extraction -> entity embedding -> scoped ANN
              -> reconcile -> statements/edges/provenance
```

## 关键决策

1. reranker 请求遵循 Cloudflare 官方 schema：`query + contexts + top_k`。
2. 当前 `@cloudflare/workers-types` 漏掉 `query` 字段，适配器用本地严格类型建模完整请求，再传给 `Ai.run`，不删运行时必填字段。
3. 图向量搜索先保存首个匹配值并完成空值收窄，不使用非空断言。
4. `useOptionalChain` 和 `noNonNullAssertion` 在 Biome 中作为 error，防止同类问题回归。

## 当前实现

- `WorkersAIProvider.rerank` 调用 `@cf/baai/bge-reranker-base`，过滤无效响应项并映射为文档下标与分数。
- 搜索服务在重排失败时保留融合结果，避免模型故障导致搜索请求失败。
- 实体 ANN 只在资产自身 scope 内检索，达到阈值后复用既有实体向量。
- 离线 eval 覆盖 lexical、dense、fused、reranked 四个阶段。
