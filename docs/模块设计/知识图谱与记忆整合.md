# 知识图谱与记忆整合

> 模块定位：从 L1 资产与切块派生 L2 语义记忆，并为检索提供可追溯的关系上下文。
>
> 对应代码：`src/features/memory/server/*`、`src/core/memory/*`、`src/platform/db/d1/schema/{entities,statements,edges,provenance,communities}.ts`、`src/platform/db/d1/repositories/d1-memory-repository.ts`
>
> 所属 M 里程碑：[`M2 知识图谱与记忆整合`](../roadmap.md#m2-知识图谱与记忆整合)
>
> 当前状态：已完成
>
> 最近更新时间：2026-07-24

## 职责与边界

- L1 assets、chunks 与 R2 快照保存原始来源和可重建内容。
- L2 entities、statements 和 edges 表达可合并、可失效的语义记忆。
- provenance 把每条派生记忆指回 L1，便于解释和重建。
- 搜索模块负责最终排序；MCP 模块负责把能力暴露给 AI 客户端。

## 结构与数据流

```text
clean asset -> entity/statement extraction
            -> scope + context entity resolution -> reconcile
            -> statements + edges + provenance(asset/chunk)

query -> entity seeds -> graph expansion -> search fusion
cron  -> duplicate/drift repair -> soft invalidation
```

## 关键决策

1. statement 同时记录有效时间和系统记录时间，支持双时间语义。
2. 调和结果限定为 ADD、UPDATE、DELETE、NOOP，保留历史和来源。
3. 实体消歧、调和与图召回必须携带 `scope_id + context_key`，同时阻止记忆域和项目
   之间串库。
4. 定时维护只做一致性修复，不按年龄自动删除个人记忆。
5. provenance 只保留 `asset_id + chunk_index + span`，直接回到 L1 来源。

## 当前实现

- L1/L2 D1 schema、repository 端口与新库初始化迁移。
- AI 实体/陈述抽取、实体向量消歧和 provenance 写入。
- 智能写调和、显著性计算、访问强化和图增强召回。
- 实体按 `scopeId + contextKey` 隔离，statement、edge 和 provenance 继续携带
  `recordKind`，支持记录类型过滤。
- 图召回读路径支持三个维度的数组过滤：Vectorize 实体种子使用 metadata `$in`，
  D1 entity/edge/statement 使用 `IN`，省略某维时不添加限制。
- scheduled consumer 覆盖 personal/agent 和全部项目，触发去重与漂移边修复。
- episode 已从 schema、repository、workflow 和 provenance 中删除；迁移会先复制
  asset/chunk 出处，再删旧表，避免级联清空证据。
